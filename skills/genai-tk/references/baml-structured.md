# BAML Structured Extraction — references/baml-structured.md

[BAML](https://docs.boundaryml.com/) is a DSL for typed LLM functions. genai-tk uses it for **structured
extraction**: a prompt that returns a validated Pydantic object instead of free text. The toolkit adds config-driven
client loading, LLM routing through its own model IDs, manifest-based incremental batch runs, and Prefect flows
that plug into the workflow engine.

Install the `baml` extra first, for example `uv add "genai-tk[baml] @ git+https://github.com/tclatos/genai-tk@main"`.
It pins `baml-py`, which also ships `baml-cli`.

Reach for BAML instead of LangChain's `with_structured_output` when the schema should be versioned and type-checked
outside Python, or when you batch-extract from many Markdown or PDF files. The cost is a `baml-cli generate` step.

## Concept Map

| Concept | What it is |
|---------|------------|
| `.baml` file | Typed function: `function ExtractResume(cv: string) -> Resume` |
| BAML client | Package generated by `baml-cli generate` with `types` and `async_client` (exposing `b`) modules |
| Config name | Entry under `structured.<name>` pointing at the client package (`default` unless `--config`) |
| `cli baml run` | Run one function on one text input (delegates to the `baml_run` workflow) |
| `cli baml extract` | Batch-process a directory of Markdown/PDF files (delegates to the `baml_extract` workflow) |
| `baml_invoke` | Low-level async call with LLM override |
| `BamlStructuredProcessor` | Batch extraction with KV-store caching |

## Setup

### 1. Write `.baml` definitions

```text
// baml_src/extract.baml
class Experience {
  company string
  role    string
  years   int
}

class Resume {
  name       string
  skills     string[]
  experience Experience[]
}

function ExtractResume(cv: string) -> Resume {
  client GPT4o
  prompt #"
    Extract structured resume data from the following text:
    {{ cv }}
    {{ ctx.output_format }}
  "#
}
```

Functions that take a `pdf` parameter receive PDF files natively from `cli baml extract`.

### 2. Generate the client

```bash
uv run baml-cli generate          # from the directory holding baml_src/
# → baml_client/types.py, baml_client/async_client.py, ...
```

Regenerate after every `.baml` change. If `baml-py` and the generated client disagree on version, loading raises
`BamlVersionMismatchError`; align the `generator` version in `baml_src/generators.baml` with the installed `baml-py`.

### 3. Point a config name at the package

```yaml
# any merged config file, e.g. config/app_conf.yaml or a file pulled in by :merge
structured:
  default:
    baml_client: baml_client          # importable package (must expose .types and .async_client.b)
  legal:
    baml_client: myapp.legal_baml_client
```

`baml_client` is the only key (`StructuredConfig`). Check it imports: `uv run python -c "import baml_client"`.

### 4. LLM routing

The `client` in the `.baml` file is a fallback. When you pass an LLM (`--llm`, `llm=`), genai-tk resolves it with
`LlmFactory` and builds a BAML `ClientRegistry` (`create_baml_client_registry`). `llm="default"` resolves the
configured default model; `llm=None` keeps the client declared in the `.baml` file.

```python
from genai_tk.extra.structured.baml_util import create_baml_client_registry

registry = create_baml_client_registry("gpt-4o-mini@openai")   # options built from the LangChain model
```

Only models that resolve to `ChatOpenAI` are supported: OpenAI itself, plus any OpenAI-compatible base URL
(OpenRouter, vLLM, LiteLLM, and so on), which map to BAML's `openai-generic` provider. Other providers raise
`ValueError: Provider not (yet?) supported for BAML`.

BAML's own logging is set to `ERROR` unless you export `BAML_LOG=debug|info|trace`.

## CLI

### `cli baml run` — one input

```bash
uv run cli baml run ExtractResume -i "John Smith; 10 years Python, ML"
cat resume.txt | uv run cli baml run ExtractResume                     # stdin
uv run cli baml run ExtractResume -i "..." --config legal --llm gpt-4o-mini@openai
uv run cli baml run ExtractResume -i "..." --out-dir ./output --out-file john.json
uv run cli baml run ExtractResume -i "..." --out-dir '${paths.data_root}' --out-file john.json --force
```

| Option | Default | Notes |
|--------|---------|-------|
| `FUNCTION_NAME` | required | Case-sensitive BAML function name |
| `--input`, `-i` | stdin | Text input |
| `--config` | `default` | Key under `structured:` |
| `--llm` | client default | Model ID or tag |
| `--out-dir`, `--out-file` | stdout | Must be given together; the file must end in `.json` |
| `--force` | false | Recompute even if the manifest has this input |

With an output, the result goes to `<out-dir>/<ReturnTypeName>/<out-file>` and a manifest skips repeated inputs.
Without one, pretty JSON is printed to stdout.

### `cli baml extract` — a directory

```bash
uv run cli baml extract ./docs ./output --function ExtractResume
uv run cli baml extract ./scans ./output --function ExtractDeliveryNote -p '**/*.pdf'
uv run cli baml extract ./reports ./output --function ExtractResume \
    -p '**/*.md' -p '!**/*_draft.md' --batch-size 10 --force
uv run cli baml extract '${paths.data_root}/reviews' '${paths.data_root}/structured' --function ExtractRainbow
```

| Option | Default | Notes |
|--------|---------|-------|
| `BASE_DIR`, `OUTPUT_DIR` | required | Positional; `${paths.*}` interpolation works (single-quote it) |
| `--function` | required | BAML function name |
| `--pathspec`, `-p` | `**/*.md` | Gitwildmatch, repeatable, `!` prefix excludes; this replaces the old `--recursive/--include/--exclude` |
| `--batch-size` | 5 | Files processed concurrently per batch |
| `--config` | `default` | Key under `structured:` |
| `--llm` | `default` | Model ID or tag |
| `--force` | false | Ignore the manifest |

Only `.md`, `.markdown`, and `.pdf` files are processed; PDFs are passed as `baml_py.Pdf`. Each output lands at
`<OUTPUT_DIR>/<ReturnTypeName>/<relative/source/path>.json`, keeping the source tree layout.

### Incremental runs

`OUTPUT_DIR/manifest.json` records, per source path, the content hash, the output path, and a schema fingerprint
(`prompt_fingerprint`, a hash of the rendered output schema from `baml_src/`). A file is skipped when both its
content and the schema are unchanged. Use `--force` once after prompt-only changes, because the fingerprint covers
the output schema, not the prompt text. Delete `manifest.json` to start over.

## Workflows and Prefect

Both CLI commands resolve the bundled `baml_run` / `baml_extract` workflows (see [workflows.md](workflows.md)), so
BAML steps can compose into pipelines. The bundled `baml_to_table` pipeline extracts and then calls `json_to_table`
to write CSV or Excel.

> **Known upstream mismatch (commit `7fbd7a3`).** The bundled `baml_extract` workflow declares `sources`,
> `json_output_dir`, and `cache_dir`, but `cli baml extract` sends `base_dir`/`output_dir` and the flow only
> accepts `base_dir`/`output_dir`. Expect `missing required parameter 'sources'` from `cli baml extract`, or
> `unexpected argument(s)` from `baml_to_table`. The `baml_run` workflow also does not forward `--out-dir`/
> `--out-file` to its flow. Until upstream fixes the YAML, either override the workflow in your own
> `workflows:` config with matching parameter names, or call the flows directly:

```python
from genai_tk.workflow.prefect.flows.baml_flow import (
    baml_single_input_flow,
    baml_structured_extraction_flow,
)

manifest = baml_structured_extraction_flow(
    "./docs",
    "./output",
    function_name="ExtractResume",
    pathspecs=["**/*.md", "!**/drafts/**"],
    batch_size=10,
    llm="gpt-4o-mini@openai",
)
print(manifest.model_name, len(manifest.entries))

result, model_name, resolved_llm, rel_path = baml_single_input_flow(
    "John Smith; SW engineer", "ExtractResume", output_dir="./output", output_file="john.json"
)
```

The flows run under Prefect's `ConcurrentTaskRunner`; see [workflows.md](workflows.md) for ephemeral versus server
mode.

## Programmatic API

### `baml_invoke`

```python
import asyncio

from genai_tk.extra.structured.baml_util import baml_invoke

resume = asyncio.run(
    baml_invoke(
        "ExtractResume",
        {"__input__": "John Smith; SW engineer, 10 yrs"},   # __input__ maps to the first parameter
        config_name="default",
        llm="gpt-4o-mini@openai",
    )
)
print(resume.name, resume.skills)
```

- Signature: `baml_invoke(function_name, params, config_name="default", llm="default", check_result_is_pydantic=False)`.
  The argument is `params`, not `inputs`.
- Multi-parameter functions take real names: `{"contract": text, "jurisdiction": "FR"}`.
- If a parameter is typed as a BAML class and you pass a `str`, it raises `TypeError` with a hint.
- Calls are wrapped in a NeMo Relay scope when `nemo_relay` is installed, so they appear in trajectories.
- It does not stream. For streaming, call `b.ExtractResume.stream(...)` from the generated client and pass
  `baml_options={"client_registry": create_baml_client_registry(...)}` yourself.

### `BamlStructuredProcessor`

```python
import asyncio

from baml_client import b
from baml_client.types import Resume
from genai_tk.extra.structured.baml_processor import BamlStructuredProcessor

processor = BamlStructuredProcessor[Resume](model_cls=Resume, baml_function=b.ExtractResume)
results = asyncio.run(processor.abatch_analyze_documents(["a", "b"], [text_a, text_b]))

by_name = BamlStructuredProcessor[Resume](
    function_name="ExtractResume",       # goes through baml_invoke, so llm= routing applies
    llm="gpt-4o-mini@openai",
    config_name="default",
    kvstore_id="default",                # key in the kv_store: config section
    force=False,
)
one = by_name.analyze_document("cv-42", markdown)          # sync helper
```

| Field | Default | Notes |
|-------|---------|-------|
| `model_cls` | `None` | Deduced from the first result if omitted, but then the cache is skipped for that batch |
| `baml_function` | `None` | Generated async method; bypasses genai-tk LLM routing |
| `function_name` | `None` | Use with `llm=` / `config_name=`; one of the two is required |
| `config_name` | `default` | Key under `structured:` |
| `llm` | `None` | Model ID; only used with `function_name` |
| `kvstore_id` | `default` | Cache store; falsy disables caching |
| `force` | false | Skip cache reads |

Cached documents are loaded by ID, the rest run concurrently with `asyncio.gather`, and successes are saved back.
Failures are logged and dropped from the result list rather than raised, so compare lengths when every document
matters. `await processor.process_files(paths)` uses each file's stem as its ID.

## Errors

All live in `genai_tk.extra.structured.exceptions` and subclass `StructuredOutputError`:

| Exception | Cause |
|-----------|-------|
| `ValueError` "BAML client package not found in config" | No `structured.<config_name>` entry |
| `BamlClientLoadError` | Package, `.types`, or `.async_client.b` not importable |
| `BamlVersionMismatchError` | Generated client and installed `baml-py` versions differ |
| `BamlFunctionNotFoundError` | Function name not in the client (case-sensitive; regenerate) |
| `BamlInvocationError` | Return type could not be validated as Pydantic |

## Anti-Patterns

- Passing `inputs=` to `baml_invoke`, or `--recursive/--include/--exclude` to `cli baml extract`: these are the
  old API. Use `params` and `-p` pathspecs.
- Importing `genai_tk.extra.structured.baml_prefect_flow`: it moved to `genai_tk.workflow.prefect.flows.baml_flow`.
- Using an Anthropic or Gemini native model ID with `--llm`: route it through an OpenAI-compatible endpoint such
  as OpenRouter, or keep the `client` declared in the `.baml` file (`llm=None`).
- Forgetting `baml-cli generate` after editing `.baml`: the old client keeps running the old schema.
- Expecting `baml_function=` to honor `llm=`: only the `function_name` path routes through genai-tk.
