# BAML Structured Extraction — references/baml-structured.md

[BAML](https://docs.boundaryml.com/) (Boundary AI Markup Language) is a domain-specific language for writing typed LLM function signatures. genai-tk integrates BAML for **structured extraction** — running a prompt that returns a validated Pydantic object instead of free-form text. The integration adds caching, batch processing, an incremental manifest, and a Prefect flow for large-scale extraction.

When to reach for BAML over LangChain's structured output: BAML gives you a versioned, type-checked schema separate from your Python code, with much better tooling for prompt iteration and a runtime that handles streaming, retries, and validation more robustly. The trade-off is an extra build step (`baml-cli generate`).

## Concept map

| Concept | What it is |
|---------|------------|
| **`.baml` file** | Typed function definition: `function ExtractResume(cv: string) -> Resume` |
| **BAML client** | Python package generated by `baml-cli generate` containing `types` (Pydantic) and `async_client` (callable functions) |
| **Config name** | Named entry under `structured.<name>` in YAML — points at the BAML client package |
| **`baml run`** | CLI: invoke a single BAML function on text input |
| **`baml extract`** | CLI: batch-process a directory of Markdown files |
| **`BamlStructuredProcessor`** | Python API: batch extraction with KV-store caching |

## Setup — four steps

### 1. Write `.baml` definitions

```
// baml_src/extract.baml

class Resume {
  name string
  skills string[]
  experience Experience[]
}

class Experience {
  company  string
  role     string
  years    int
}

function ExtractResume(cv: string) -> Resume {
  client GPT4o
  prompt #"
    Extract structured resume data from the following text:
    {{ cv }}
  "#
}
```

### 2. Generate the Python client

```bash
# From the directory containing baml_src/
baml-cli generate
# → creates baml_client/types.py + baml_client/async_client.py + ...
```

### 3. Configure the client package in YAML

```yaml
# config/overrides.yaml (or any merged file)
structured:
  default:
    baml_client: baml_client      # importable Python package

  legal_docs:                     # alternative config
    baml_client: myapp.legal_baml_client
```

The package must be importable — verify with `uv run python -c "import baml_client"`.

### 4. The LLM is wired automatically

BAML uses its own `ClientRegistry` for LLM routing, but genai-tk maps your standard `model_id@provider` to a BAML client via `create_baml_client_registry()` — so you can pass `--llm gpt_4o@openai` to BAML CLI commands or `llm="gpt_4o@openai"` to the programmatic API and it Just Works.

If you need to inspect the registry directly:

```python
from genai_tk.extra.structured.baml_util import create_baml_client_registry
registry = create_baml_client_registry("gpt_4o@openai")
```

## CLI

### `baml run` — single invocation

```bash
# Inline text
cli baml run ExtractResume -i "John Smith; 10 years Python, ML"

# Stdin
cat resume.txt | cli baml run ExtractResume

# Override config / LLM
cli baml run ExtractResume -i "..." --config legal_docs --llm gpt_4o@openai

# Save to JSON file
cli baml run ExtractResume -i "..." \
    --out-dir ./output --out-file john_smith.json

# Force overwrite
cli baml run ExtractResume -i "..." \
    --out-dir ./output --out-file john.json --force
```

Output goes to `<out-dir>/<ModelName>/<out-file>` so results from different functions are auto-organised by their return type. Without `--out-dir`, the JSON is pretty-printed to stdout.

### `baml extract` — batch directory processing

Processes every matching Markdown file in a directory and writes one JSON per input.

```bash
# Basic
cli baml extract ./docs ./output --function ExtractRainbow

# Recursive
cli baml extract ./docs ./output --recursive --function ExtractRainbow

# Filters
cli baml extract ./reports ./output \
    --include 'report_*.md' --include 'summary_*.md' \
    --exclude '*_draft.md' \
    --recursive --function ExtractRainbow

# Force re-extract (ignore manifest)
cli baml extract ./docs ./output --recursive --function ExtractRainbow --force

# Config-interpolated paths (note single quotes!)
cli baml extract '${paths.data_root}/docs' '${paths.data_root}/structured' \
    --recursive --function ExtractRainbow \
    --batch-size 10 --force
```

Options:

| Option | Default | Description |
|--------|---------|-------------|
| `--function TEXT` | required | BAML function name (case-sensitive) |
| `--recursive` | false | Recurse into sub-directories |
| `--force` | false | Re-extract even if file is unchanged |
| `--batch-size N` | 10 | Concurrent tasks per Prefect batch |
| `--include PATTERN` | all | Glob include (repeatable) |
| `--exclude PATTERN` | none | Glob exclude (repeatable) |
| `--config TEXT` | default | Config name under `structured.<name>` |
| `--llm TEXT` | default | LLM override |

#### Incremental processing — `manifest.json`

`baml extract` maintains a `manifest.json` in the output directory that records:

- Source file hash
- Output JSON path
- **BAML schema fingerprint** (SHA-256 of the function definition)
- Processing timestamp

On subsequent runs, files are skipped when neither the source content nor the BAML function definition has changed. Large batch re-runs become fast (often near-instant for unchanged corpora).

The manifest is stored **per function name** — different BAML functions writing to the same output directory don't interfere.

To force a full re-run after a schema change: pass `--force` once, or delete `manifest.json`.

## Programmatic API

### `baml_invoke` — low-level async call

```python
import asyncio
from genai_tk.extra.structured.baml_util import baml_invoke

result = asyncio.run(
    baml_invoke(
        function_name="ExtractResume",
        inputs={"__input__": "John Smith; SW engineer, 10 yrs"},
        config_name="default",
        llm="gpt_4o@openai",
    )
)
# result is a validated Pydantic instance matching the BAML return type
print(result.name, result.skills)
```

The `__input__` key is a convention for single-input functions — for multi-arg BAML functions, use the actual parameter names.

### `BamlStructuredProcessor` — batch with KV caching

The recommended interface for processing many documents. Generic over the return type, with KV-store caching keyed by `doc_id`.

```python
import asyncio
from genai_tk.extra.structured.baml_processor import BamlStructuredProcessor
from baml_client import b                        # generated async client
from baml_client.types import Resume

processor = BamlStructuredProcessor[Resume](
    model_cls=Resume,
    baml_function=b.ExtractResume,               # pass the async method directly
    kvstore_id="file",                           # file-based KV cache (or "memory", etc.)
)

document_ids = ["doc_1", "doc_2", "doc_3"]
contents = [open(f).read() for f in ["a.md", "b.md", "c.md"]]

results: list[Resume] = asyncio.run(
    processor.abatch_analyze_documents(document_ids, contents)
)
```

Or use the function name (handy when the BAML client isn't imported at the call site):

```python
processor = BamlStructuredProcessor[Resume](
    function_name="ExtractResume",
    llm="gpt_4o@openai",
    config_name="default",
    force=False,                                 # True bypasses cache
)
```

**Caching semantics:**

- Already-processed documents (matched by `doc_id`) load from the KV store
- Only uncached documents are sent to BAML — all concurrently via `asyncio.gather`
- Results are written back after successful processing
- `force=True` bypasses the cache and reprocesses everything

`kvstore_id` accepts any tag from the toolkit's KV store registry — `"file"`, `"memory"`, or custom entries from your `kvstore:` YAML.

## How BAML fits the stack

```
BAML .baml files
    │
    ▼  baml-cli generate
baml_client/
    ├── types.py          ← Pydantic models for all BAML types
    └── async_client.py   ← b.ExtractResume(), b.FakeResume(), …
    │
    ▼  loaded dynamically by load_baml_client()
genai_tk.extra.structured
    ├── baml_util.py            ← load_baml_client, baml_invoke, ClientRegistry wiring
    ├── baml_processor.py       ← BamlStructuredProcessor (KV-cached batch)
    └── baml_prefect_flow.py    ← Prefect flow for directory-level extraction
    │
    ▼  CLI layer
genai_tk.extra.structured.commands_baml
    ├── baml run        ← single-item invocation
    └── baml extract    ← Prefect-backed batch extraction
```

`baml extract` runs through Prefect under the hood, so you get parallelism, retries, and a flow run UI if you have a Prefect server running. See the project's `docs/prefect.md` for ephemeral vs. server mode.

## Configuration reference

```yaml
structured:
  default:
    baml_client: baml_client          # importable Python package (required)

  custom:
    baml_client: myapp.other_client   # different BAML client for a different domain
```

That's the entirety of the BAML-specific config. LLM wiring and KV store come from the toolkit's standard config.

## Patterns

### Batch extraction with progress

For 1000s of documents:

```python
from genai_tk.extra.structured.baml_processor import BamlStructuredProcessor
from baml_client import b
from baml_client.types import Invoice

processor = BamlStructuredProcessor[Invoice](
    function_name="ExtractInvoice",
    llm="gpt41mini@openai",                     # cheap model for the bulk
    kvstore_id="file",
)

# Or via the prefect flow for batched parallelism + retries
from genai_tk.extra.structured.baml_prefect_flow import baml_extraction_flow
from genai_tk.extra.prefect.runtime import run_flow_ephemeral

result = run_flow_ephemeral(
    baml_extraction_flow,
    input_dir="./invoices",
    output_dir="./extracted",
    function_name="ExtractInvoice",
    recursive=True,
    batch_size=20,
    config_name="default",
    llm="gpt41mini@openai",
)
```

### Schema evolution

When you change a BAML function's return type:

1. Edit `.baml` file
2. Run `baml-cli generate` to regenerate `baml_client/`
3. Run `cli baml extract --force` once to invalidate the manifest

The schema fingerprint in the manifest will change, so without `--force`, files would be re-extracted anyway — but `--force` makes the intent explicit.

### Mixing models per function

Different BAML functions can use different LLMs by overriding at call time:

```bash
cli baml run ExtractInvoice -i "..." --llm gpt41mini@openai      # cheap
cli baml run ClassifyContract -i "..." --llm gpt_4o@openai       # accurate
```

Or in BAML itself by referencing different `client` directives in `.baml` files — but routing through genai-tk's `--llm` keeps the model choice in your config layer rather than hard-coded in the prompts.

## Troubleshooting

**`ValueError: BAML client package not found in config`** — `structured.default.baml_client` isn't set, or the package isn't importable. Check `cli info config` for the active configuration and verify with `uv run python -c "import baml_client"`.

**`BAML function not found`** — Function names are case-sensitive. `ExtractResume` is not the same as `extractResume`. The function must be defined in a `.baml` file and the client must have been regenerated since.

**Manifest doesn't pick up schema changes** — The fingerprint is over the full BAML function definition string. If your generation pipeline produces deterministic output, this works automatically. If it doesn't, force the first run after a schema change with `--force`.

**LLM override seems ignored** — Make sure you're passing `--llm` (CLI) or `llm=` (programmatic). BAML's own `client` directive in the `.baml` file is overridden by the toolkit's wiring; if you bypass `baml_invoke` and call the BAML client directly, you skip the wiring.

**Streaming partial results** — `baml_invoke` is non-streaming. If you need streaming, use the BAML async client directly (`b.ExtractResume.stream(...)`) and handle `ClientRegistry` setup yourself with `create_baml_client_registry()`.
